# テクニカル FAQ: FSx for ONTAP AI メタデータカタログ

> 制限事項と制約を含む事実ベースの回答集。

---

## 一般

### Q: ファイルのコピーは必要ですか？

**A:** 不要です。本ソリューションは FSx for ONTAP の S3 Access Point を使い、ファイル内容をインプレースで読み取ります（ゼロコピーストレージ）。ファイルは FSx for ONTAP ボリュームから移動しません。外部に保存されるのは抽出されたメタデータ（S3 Tables）のみです。

**「ゼロコピーストレージ」の補足:** ファイルバイトが別のストレージに複製されることはありません。ただし AI 処理中、ファイル内容は Lambda メモリ上で一時的にアクセスされます（一時的であり、ソース FSx for ONTAP ボリューム外に永続化されません）。

---

### Q: セキュリティ管理はどうなっていますか？

**A:** ファイルは既存のアクセス制御（NFS/SMB パーミッション）が適用された FSx for ONTAP 上に残ります。AI パイプラインを通過するのはメタデータのみです。ガバナンスは以下で担保されます：
- **AWS Lake Formation**: メタデータテーブルへのきめ細かなアクセス制御
- **AWS CloudTrail**: 全 API 呼び出しの完全な監査証跡
- **IAM Policies**: S3 Access Points および Bedrock への最小権限アクセス
- **VPC Private Endpoints**: 全トラフィックが VPC 内に留まる

---

### Q: コストの目安は？

**A:** 100,000 ファイル、日次 1,000 件変更の場合、約 **$114/月** です（平均ファイルサイズ 100KB–1MB 想定）。

ファイルサイズ別 Bedrock コスト：
| ファイルサイズ | ファイルあたり概算コスト |
|-------------|:--------------------:|
| 1 KB テキスト | ~$0.01 |
| 100 KB ドキュメント | ~$0.05 |
| 1 MB PDF | ~$0.07 |
| 10 MB 画像 | ~$0.15 |

実際のコストはプロンプトの複雑さと出力トークン数に依存します。コストはファイルアクティビティに比例してスケールします。アイドルコスト: ~$5/月。

詳細は [コスト見積もり](./cost-estimation-ja.md) を参照。

---

### Q: AI 分類の精度は？

**A:** PoC テストでは、ビジネス文書混在のテストデータセットで **平均信頼度 0.94** を達成しました。

**重要な注意点:** これは特定のテストデータセットでの PoC 精度です。本番精度は以下により変動します：
- ファイル種別（テキスト文書はスキャン画像より精度が高い）
- 言語ミックス（単一言語コンテンツの方が混在より精度が高い）
- ドメイン用語（専門用語はプロンプトチューニングが必要な場合あり）
- ファイル品質（低品質スキャン、手書きメモは精度低下）

特定環境での精度検証には、実際の対象ファイルを用いた PoC を推奨します。

## 制約事項

### Q: 本ソリューションで動作しないものは？

**A:** 主な制約：

| 制約 | 影響 |
|------|------|
| S3 AP はこのパイプラインで読み取り専用（API レベルでは書き込みサポート） | 分析ツールから FSx for ONTAP ボリュームへの結果書き戻し不可 |
| S3 AP 経由の S3 Event Notifications 非対応 | Snowpipe、EventBridge ルール、バケット通知の自動トリガー不可 |
| FPolicy レイテンシ付加 | NAS クライアントのファイル操作に ~1–5ms |
| Lambda 一時処理 | ファイル内容が Lambda メモリを通過（処理層では「ゼロデータ移動」ではない） |
| Athena コールドスタート | アイドル後の初回クエリで 3–5 秒追加 |
| OpenSearch ウォームアップ | サーバーレス OCU 割り当てに長時間アイドル後 10–30 秒 |
| S3 Tables は比較的新しい | GA 2024年12月; 一部クロスプラットフォーム統合は進化中 |

---

### Q: 分析ツールから S3 Access Point 経由で FSx for ONTAP に書き戻せますか？

**A:** いいえ。FSx for ONTAP の S3 Access Point は本パイプラインでは**読み取り専用**で使用されます。分析ワークフローが結果の書き戻しを必要とする場合、別の S3 バケットや他のストレージに書き込む必要があります。

---

### Q: FPolicy は NAS パフォーマンスに影響しますか？

**A:** 軽微に影響します。FPolicy はファイル操作（作成、変更、削除、リネーム）あたり約 **1–5ms のレイテンシ**を NAS クライアントに付加します。多くのワークロードでは感知できませんが、レイテンシに敏感なアプリケーション（例: 高頻度取引データフィード、リアルタイム映像編集）はテストが必要です。

FPolicy は特定のボリューム/共有およびイベントタイプにスコープを限定して影響を最小化できます。

---

### Q: S3 Access Point から Snowpipe や EventBridge をトリガーできますか？

**A:** いいえ。FSx for ONTAP の S3 Access Point は **S3 Event Notifications に非対応**です：
- Snowpipe は S3 AP 経由のファイル変更で自動トリガーできない
- EventBridge ルールは S3 AP イベントでトリガーできない
- S3 バケット通知設定は S3 AP に適用されない

回避策は FPolicy → Lambda → 直接 API 呼び出し（Snowpipe REST API、EventBridge PutEvents 等）であり、本ソリューションはこの方式で動作します。

## プラットフォーム統合

### Q: Snowflake は使えますか？

**A:**
- **Cortex File AI**: 検証済み ✅ — presigned URL 経由でファイル処理可能
- **S3 Tables カタログ経由の Iceberg テーブルクエリ**: Snowflake 側の機能サポート待ち。Snowflake の S3 Tables Iceberg カタログ統合はまだ利用不可。
- **回避策**: メタデータを Parquet 形式で S3 にエクスポートし、Snowflake 外部テーブルでアクセス

---

### Q: Databricks は使えますか？

**A:**
- **Foreign Catalog 経由の直接 S3 Tables アクセス**: 評価中。Databricks の S3 Tables 向け Foreign Catalog サポートは進化中（2026-06 時点）。
- **回避策**: DataSync でメタデータを Databricks アクセス可能な S3 バケットにコピー、または Iceberg メタデータを Databricks 管理場所にエクスポート。

---

### Q: Amazon Athena のパフォーマンスは？

**A:** S3 Tables Iceberg に対する Athena クエリは分析ワークロードに適しています：
- **コールドスタート**: アイドル後の初回クエリは 3–5 秒追加
- **後続クエリ**: データ量に応じてサブ秒〜数秒
- **パーティションプルーニング**: パーティション列（例: scan_date）でフィルタ時に有効

---

### Q: OpenSearch Serverless のパフォーマンスは？

**A:** OpenSearch Serverless はベクトル + キーワード検索を提供：
- **ウォームアップ時間**: 長時間アイドル後、OCU 割り当てに 10–30 秒
- **ウォーム後**: ベクトル類似度・キーワード検索ともにサブ秒レスポンス
- **スケールトゥゼロ**: アイドル中のコストを最小化するがウォームアップレイテンシが発生

---

## 技術詳細

### Q: 使用する AI モデルは？

**A:**
- **Amazon Bedrock Claude**（Anthropic）: ファイル分類、コンテンツ抽出、ビジョン（画像/PDF 分析）
- **Amazon Titan Embeddings**: セマンティック類似度検索用のベクトル埋め込み
- **Amazon Comprehend**: PII 検出（氏名、住所、電話番号等）

すべてのモデルは AWS アカウント内で実行されます。データはアカウントまたはリージョン外に出ません。

---

### Q: PII 検出について？

**A:** PII は Amazon Comprehend を使い英語・日本語コンテンツで自動検出されます。検出された PII は：
1. PII タイプと信頼度スコアとともにメタデータにフラグ付け
2. OpenSearch へのインデックス前に任意でリダクション（設定可能）
3. Athena クエリによるコンプライアンスレポートで利用可能

---

### Q: オンプレミス ONTAP でも使えますか？

**A:** はい。2 つのパスがあります：
1. **SnapMirror → FSx for ONTAP**: オンプレミスボリュームを FSx for ONTAP にミラーし、FSx for ONTAP コピーに AI パイプラインを適用。ゼロコピーストレージの利点を維持。
2. **AWS DataSync**: オンプレミスから S3 への直接ファイル転送で処理。

## PoC 検証

### Q: PoC では何をしますか？

**A:** 通常 1–2 週間で完全な検証を実施：
- 第 1 週: インフラデプロイ + AI パイプライン設定 + 初期分類
- 第 2 週: 精度チューニング + ダッシュボード設定 + 受入テスト

最小限のデモンストレーションは CloudFormation とサンプルデータを使い **30 分**で実行可能。

詳細は [PoC 実行ガイド](../implementation-guide/poc-execution-guide-ja.md) を参照。
