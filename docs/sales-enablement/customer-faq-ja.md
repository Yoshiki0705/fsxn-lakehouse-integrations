# カスタマー FAQ: FSx for ONTAP AI メタデータカタログ

> 制限事項と制約を含む正直な回答集

---

## 一般

### Q: ファイルをコピーする必要がありますか？

**A:** いいえ。FSx for ONTAP の S3 Access Point でファイルをその場で読み取ります（ゼロコピーストレージ）。ファイルは FSx for ONTAP ボリュームから移動しません。外部に格納されるのは S3 Tables 上の抽出メタデータのみです。

**「ゼロコピーストレージ」の補足:** ファイルバイトは別のストレージに複製されません。ただし AI 処理中、ファイルコンテンツは Lambda メモリ内で一時的にアクセスされます（一時的であり、ソース FSx for ONTAP ボリューム外に永続化されません）。

---

### Q: セキュリティとコンプライアンスはどうなっていますか？

**A:** ファイルは既存のアクセス制御（NFS/SMB 権限）を維持したまま FSx for ONTAP 上に残ります。AI パイプラインを通るのはメタデータのみです。ガバナンスは以下で実現：
- **AWS Lake Formation**: メタデータテーブルへのきめ細かいアクセス制御
- **AWS CloudTrail**: 全 API コールの完全な監査証跡
- **IAM ポリシー**: S3 Access Point と Bedrock への最小権限アクセス
- **VPC プライベートエンドポイント**: 全トラフィックは VPC 内で完結

---

### Q: コストはどのくらいですか？

**A:** 10 万ファイル、1 日 1,000 件変更（平均 100KB–1MB）で月額約 **$114** です。

ファイルサイズ別 Bedrock コスト：
| ファイルサイズ | 1 ファイルあたりコスト |
|-------------|:------------------:|
| 1 KB テキスト | ~$0.01 |
| 100 KB ドキュメント | ~$0.05 |
| 1 MB PDF | ~$0.07 |
| 10 MB 画像 | ~$0.15 |

実際のコストはプロンプトの複雑さと出力トークン数に依存。事前コミットメント不要 — ファイル更新頻度に比例。アイドル時: ~$5/月。

---

### Q: AI 分類の精度はどのくらいですか？

**A:** PoC テストで混合ビジネス文書のテストデータセットに対し**平均信頼度 0.94** を達成。

**重要な注意事項:** これは特定テストデータセットでの PoC 精度です。本番精度は以下により変動します：
- ファイルタイプ（テキスト文書はスキャン画像より高精度）
- 言語構成（単一言語の方が混在言語より高精度）
- ドメイン用語（専門用語はプロンプトチューニングが必要な場合あり）
- ファイル品質（低品質スキャン、手書きメモは精度低下）

実環境のファイルで精度を検証する 1–2 週間の PoC を推奨します。

## 制限事項 & 制約

### Q: このソリューションでできないことは何ですか？

**A:** 把握すべき主な制約：

| 制限事項 | 影響 |
|---------|------|
| S3 AP はこのパイプラインでは読み取り専用で使用（書き込みもサポート） | 分析ツールから FSx for ONTAP ボリュームへの書き戻し不可 |
| S3 AP 経由の S3 Event Notifications 非対応 | Snowpipe、EventBridge ルール、バケット通知の自動トリガー不可 |
| FPolicy のレイテンシ追加 | NAS クライアントのファイル操作ごとに ~1–5ms |
| Lambda 一時的処理 | ファイルコンテンツが Lambda メモリを通過（処理レイヤーでは「ゼロデータ移動」ではない） |
| Athena コールドスタート | アイドル後の最初のクエリ: 3–5 秒追加 |
| OpenSearch ウォームアップ | 長時間アイドル後の OCU 割り当てに 10–30 秒 |
| S3 Tables は比較的新しい | 2024年12月 GA。一部のクロスプラットフォーム統合は発展途上 |

---

### Q: 分析ツールから S3 Access Point 経由で FSx for ONTAP に書き戻せますか？

**A:** いいえ。FSx for ONTAP の S3 AP はこのパイプラインでは読み取り専用で使用（**書き込みもサポート**）です。分析ワークフローでストレージへの書き戻しが必要な場合、結果は別の S3 バケットまたは他のストレージに書き込む必要があります。

---

### Q: FPolicy は NAS パフォーマンスに影響しますか？

**A:** はい、軽微に。FPolicy は NAS クライアントのファイル操作（作成、変更、削除、リネーム）ごとに約 **1–5ms のレイテンシ**を追加します。多くのワークロードでは体感できませんが、レイテンシに敏感なアプリケーション（高頻度取引データフィード、リアルタイム動画編集等）はテストすべきです。

FPolicy は特定のボリューム/共有やイベントタイプに限定して影響を最小化できます。

---

### Q: S3 Access Point から Snowpipe や EventBridge をトリガーできますか？

**A:** いいえ。FSx for ONTAP の S3 Access Point は **S3 Event Notifications をサポートしません**。つまり：
- S3 AP 経由のファイル変更で Snowpipe は自動トリガーされない
- EventBridge ルールは S3 AP イベントでトリガーされない
- S3 バケット通知設定は S3 AP に適用されない

回避策として FPolicy → Lambda → 直接 API コール（Snowpipe REST API、EventBridge PutEvents 等）を使用します。本ソリューションはこの方式で動作しています。

## プラットフォーム統合

### Q: Snowflake は使えますか？

**A:**
- **Cortex File AI**: 検証済み ✅ — presigned URL 経由でファイル処理可能
- **S3 Tables カタログ経由の Iceberg テーブルクエリ**: Snowflake 側の機能対応待ち。S3 Tables を Iceberg カタログとして使用する統合はまだ利用不可。
- **回避策**: メタデータを Parquet 形式で S3 にエクスポートし、Snowflake 外部テーブルでアクセス

---

### Q: Databricks は使えますか？

**A:**
- **Foreign Catalog 経由の直接 S3 Tables アクセス**: 評価中。Databricks の S3 Tables 向け Foreign Catalog サポートは発展途上（2026-06 時点）。
- **回避策**: DataSync でメタデータを Databricks がアクセス可能な S3 バケットにコピー、または Iceberg メタデータを Databricks 管理ロケーションにエクスポート。

---

### Q: Amazon Athena のパフォーマンスは？

**A:** S3 Tables Iceberg に対する Athena クエリは分析ワークロードで良好に動作します。注意点：
- **コールドスタート**: アイドル後の最初のクエリに 3–5 秒の追加レイテンシ
- **後続クエリ**: データ量に応じてサブ秒〜数秒
- **パーティションプルーニング**: パーティション列（例: scan_date）でフィルタすると効果的

---

### Q: OpenSearch Serverless のパフォーマンスは？

**A:** OpenSearch Serverless はベクトル + キーワード検索を提供。注意点：
- **ウォームアップ時間**: 長時間アイドル後、OCU 割り当てに 10–30 秒
- **ウォーム後**: ベクトル類似検索・キーワード検索ともにサブ秒レスポンス
- **スケールトゥゼロ**: アイドル時のコスト最小化。ただしウォームアップレイテンシが発生

---

## 技術詳細

### Q: どの AI モデルが使われていますか？

**A:**
- **Amazon Bedrock Claude** (Anthropic): ファイル分類、コンテンツ抽出、ビジョン（画像/PDF 解析）
- **Amazon Titan Embeddings**: セマンティック類似検索用ベクトル埋め込み
- **Amazon Comprehend**: PII 検出（氏名、住所、電話番号等）

すべてのモデルは AWS アカウント内で実行。データがアカウント・リージョン外に出ることはありません。

**精度の注意:** Bedrock 分類精度はファイルタイプと言語により変動。テストデータセットでの PoC 精度であり、本番精度はファイル構成に依存。

---

### Q: PII 検出はどうなっていますか？

**A:** Amazon Comprehend で英語・日本語の両方の PII を自動検出。検出された PII は：
1. メタデータに PII タイプと信頼度スコアをフラグ付け
2. OpenSearch インデックス前にオプションでマスキング（設定可能）
3. Athena クエリによるコンプライアンスレポートに利用可能

---

### Q: オンプレミスの ONTAP でも使えますか？

**A:** はい。2 つのパス：
1. **SnapMirror → FSx for ONTAP**: オンプレボリュームを FSx for ONTAP にミラーリングし、FSx for ONTAP コピーに AI パイプラインを適用。ゼロコピーストレージの利点を維持。
2. **AWS DataSync**: オンプレから S3 への直接ファイル転送。
