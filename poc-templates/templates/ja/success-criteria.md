## Go / No-Go 判断

### Go 条件（全て真であること）

- [ ] Tier 1 基準が全てパス
- [ ] 未解決のセキュリティ懸念なし
- [ ] 顧客がビジネス価値を確認
- [ ] コストが許容範囲内
- [ ] 運用モデルが持続可能

### No-Go 条件（いずれかで No-Go）

- [ ] 正しい設定後もクエリが失敗（プラットフォーム制限）
- [ ] FSx スループット影響が許容閾値を超過
- [ ] セキュリティ/ガバナンス要件を満たせない
- [ ] コストが予算の 2 倍超
- [ ] 顧客の必須テーブルフォーマット（Delta/Iceberg write）が S3 AP で非サポート

### Adjust 条件（部分的成功 — 再設計必要）

- [ ] 読み取りは動作するが書き込みは不可 → ハイブリッドパターン使用（FSx 読み取り + S3 書き込み）
- [ ] 動作するがガバナンス不十分 → Lake Formation または Snowflake ガバナンスレイヤー追加
- [ ] 動作するがレイテンシが高い → FSx スループット増加またはキャッシュレイヤー使用
- [ ] 動作するが同期が必要 → S3 を要求するプラットフォーム向けに DataSync 追加（Databricks）
