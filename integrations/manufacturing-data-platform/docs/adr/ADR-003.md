# ADR-003: Use FSx for ONTAP as Payload Storage for Large Unstructured Data

## Status

**Accepted** — 2026-06-07

## Context / コンテキスト

Manufacturing environments generate large unstructured payloads (quality inspection images, video recordings, technical documents, CAD files) alongside structured events. These payloads are too large for Kafka (recommended ≤1 MB) and require enterprise data protection features. Factory systems typically write data via NFS or SMB protocols, while analytics consumers need S3 API access.

製造環境は構造化イベントとともに大容量非構造化ペイロード（品質検査画像、動画記録、技術文書、CAD ファイル）を生成する。これらのペイロードは Kafka には大きすぎ（推奨 ≤1 MB）、エンタープライズデータ保護機能が必要。工場システムは通常 NFS または SMB プロトコルでデータを書き込み、分析コンシューマーは S3 API アクセスが必要。

## Decision / 決定

Use Amazon FSx for NetApp ONTAP as the storage layer for large unstructured payloads, leveraging multiprotocol access (NFS/SMB/S3) and ONTAP data protection services (Snapshot, SnapMirror).

Amazon FSx for NetApp ONTAP を大容量非構造化ペイロードのストレージレイヤーとして使用し、マルチプロトコルアクセス（NFS/SMB/S3）と ONTAP データ保護サービス（Snapshot、SnapMirror）を活用する。

## Options Considered / 検討したオプション

| Option | Pros | Cons |
|--------|------|------|
| **FSx for ONTAP** | Multiprotocol (NFS/SMB/S3); Snapshot; SnapMirror; FlexClone; dedup/compression; existing factory NFS/SMB compatibility | Higher per-GB cost than S3; operational complexity; ONTAP knowledge required |
| Native Amazon S3 | Lowest cost per GB; fully managed; native analytics integration; unlimited scale | S3 only (no NFS/SMB); requires factory system migration; per-object versioning (costly at scale); no instant clone |
| Amazon EFS | Managed NFS; scales automatically | No SMB; no S3 access; no snapshots equivalent to ONTAP; limited data protection |
| FSx for Windows | SMB native; AD integration | No NFS; no S3; limited data protection compared to ONTAP |
| On-premises NAS + DataSync | Leverage existing infrastructure | Latency; bandwidth constraints; no S3 API; complex DR |

## Consequences / 結果

### Positive / ポジティブ

- Factory systems continue writing via NFS/SMB without application changes
- Analytics consumers (Lambda, Bedrock, SageMaker) access same data via S3 protocol
- ONTAP Snapshot provides space-efficient point-in-time recovery for entire payload sets
- FlexClone enables instant, zero-copy data provisioning for PoC/dev/test
- SnapMirror provides cross-region DR without full data copy
- Deduplication reduces storage cost for similar payload versions (images from same inspection line)

### Negative / ネガティブ

- Higher per-GB cost than native S3 (justified by multiprotocol + data services)
- Requires ONTAP operational knowledge
- Cannot be used as Delta Lake storage target (no atomic rename)
- Not directly governed by Unity Catalog
- S3 Access Points feature has known limitations with third-party platforms

## Risks / リスク

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Over-positioning FSx for ONTAP for workloads where S3 suffices | Medium | Medium | Clear criteria: use FSx for ONTAP only when multiprotocol or ONTAP data services are needed |
| Operational complexity for teams unfamiliar with ONTAP | Medium | Medium | Document operational runbooks; use managed service features |
| Cost growth with payload volume | Medium | High | FabricPool tiering for cold payloads; capacity planning |
| Payload access latency from Databricks notebooks | Low | Low | Use boto3 with appropriate IAM role; acceptable for ad-hoc access |
