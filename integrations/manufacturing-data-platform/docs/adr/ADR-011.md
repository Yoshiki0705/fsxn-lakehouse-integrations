# ADR-011: Unity Catalog Permissions Model

## Status

**Accepted** — 2026-06-07

## Context / コンテキスト

Delta tables produced by the Kafka→Databricks streaming pipeline must be governed by Unity Catalog. The permissions model must define who can read/write which tables, how factory-level data isolation works, and how payload access (FSx for ONTAP) relates to table access.

Kafka→Databricks ストリーミングパイプラインが生成する Delta テーブルは Unity Catalog により管理されなければならない。権限モデルは誰がどのテーブルを読み書きできるか、工場レベルのデータ分離がどう機能するか、ペイロードアクセス（FSx for ONTAP）がテーブルアクセスとどう関係するかを定義する必要がある。

## Decision / 決定

Implement a **catalog-per-environment, schema-per-factory** hierarchy with role-based access control.

**環境ごとのカタログ、工場ごとのスキーマ**階層をロールベースアクセス制御で実装する。

## Catalog Hierarchy / カタログ階層


## Payload Access Governance / ペイロードアクセスガバナンス

Unity Catalog governs structured data (Delta tables). Payload files on FSx for ONTAP are governed separately. The relationship:

```
Delta table (UC governed)          FSx for ONTAP (ONTAP governed)
┌─────────────────────┐            ┌──────────────────────────┐
│ quality_events      │            │ /vol_images/             │
│   event_id          │            │   factory-alpha/         │
│   payload_uri  ─────┼───────────→│     line-A1/            │
│   payload_type      │  reference │       2026/06/07/       │
│   checksum_sha256   │  (not copy)│         quality_xxx.jpg │
└─────────────────────┘            └──────────────────────────┘
     ↑ UC RBAC                          ↑ NFS export policy
                                        ↑ Security groups
```

| Access Scenario | UC Permission | ONTAP Permission | Both Required |
|----------------|--------------|-----------------|---------------|
| Query quality_events table | SELECT on schema | Not needed (metadata only) | UC only |
| Read payload_uri column value | SELECT on schema | Not needed (URI is just a string) | UC only |
| Actually download the payload file | — | NFS/S3 access to FSx volume | ONTAP only |
| Query + download payload | SELECT on schema | NFS/S3 access | Both |

**Design principle:** Reading Delta tables (including payload_uri) requires UC permission only. Actually accessing the payload file requires separate FSx for ONTAP access. This provides defense-in-depth: even if a user can see a payload_uri, they cannot access the file without ONTAP-level authorization.

## Lineage and Audit / リネージと監査

| Aspect | Mechanism |
|--------|-----------|
| Table lineage | Unity Catalog automatic lineage tracking |
| Column lineage | UC column-level lineage (when available) |
| Query audit | UC audit logs (who queried what, when) |
| Payload access audit | ONTAP audit log (NFS/S3 access events) |
| Pipeline provenance | _system.ingestion_metrics (Kafka offset → table row mapping) |

## Consequences / 結果

### Positive / ポジティブ

- Factory-level data isolation via schemas (multi-tenant within same workspace)
- Streaming pipeline has minimal required permissions (INSERT only)
- Cross-factory views provide governed aggregation without exposing raw per-factory data
- Payload access requires separate authorization (defense in depth)
- Audit trail covers both structured and unstructured access

### Negative / ネガティブ

- Schema-per-factory adds management overhead for many factories (acceptable for PoC with 2)
- UC permissions don't extend to FSx for ONTAP (split governance, per RSK-009)
- No automatic linkage between UC permissions and ONTAP export policies
- Role proliferation if many factories and teams (future: consider attribute-based access)
