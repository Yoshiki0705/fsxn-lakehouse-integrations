# ADR-014: MSK Serverless → Provisioned Migration for ClickHouse Cloud Connectivity

## Status

**Accepted** — 2026-06-07

## Context / コンテキスト

During Phase A PoC deployment, we discovered that ClickHouse Cloud ClickPipes cannot connect to MSK Serverless. Two constraints were identified:

1. **MSK Serverless does not support Multi-VPC connectivity** — ClickHouse Cloud runs in a separate VPC and requires PrivateLink (Multi-VPC) to reach MSK brokers.
2. **MSK `kafka.t3.small` does not support Multi-VPC connectivity** — Only `kafka.m5.large` and larger instances support this feature.

Phase A デプロイ中に、ClickHouse Cloud ClickPipes が MSK Serverless に接続できないことが判明。2つの制約を特定：

1. **MSK Serverless は Multi-VPC connectivity をサポートしない** — ClickHouse Cloud は別 VPC にあり、MSK ブローカーへの到達に PrivateLink（Multi-VPC）が必要。
2. **MSK `kafka.t3.small` は Multi-VPC connectivity をサポートしない** — `kafka.m5.large` 以上のインスタンスのみサポート。

## Decision / 決定

Replace MSK Serverless with **MSK Provisioned (`kafka.m5.large` × 2 brokers)** with Multi-VPC connectivity enabled.

MSK Serverless を **MSK Provisioned (`kafka.m5.large` × 2 ブローカー)** + Multi-VPC connectivity 有効に置き換える。

## Evidence / エビデンス

### Error Observed

```
dial tcp: lookup boot-9dycmry4.c1.kafka-serverless.ap-northeast-1.amazonaws.com on 172.20.0.10:53: no such host
```

### AWS Error on t3.small

```
BadRequestException: Multi-VPC private connectivity is not supported on the broker instance type of the MSK cluster.
```

### Confirmed Requirements

| Requirement | Value | Source |
|-------------|-------|--------|
| Multi-VPC minimum instance | `kafka.m5.large` | AWS error message + docs |
| MSK Serverless Multi-VPC | Not supported | Testing + AWS docs |
| ClickPipes MSK connectivity | Requires Multi-VPC or public endpoint | ClickHouse docs + testing |

## Cost Impact / コスト影響

| Item | MSK Serverless (original) | MSK Provisioned (new) | Delta |
|------|--------------------------|----------------------|-------|
| Monthly cost (PoC) | $50-150 | ~$300 | +$150-250 |
| Instance | N/A (serverless) | kafka.m5.large × 2 | Fixed |
| Storage | Per-use | 10 GB × 2 (minimum) | Fixed |

**Mitigation**: Delete MSK cluster immediately after PoC validation completes. Don't leave running idle.

## Consequences / 結果

### Positive

- ClickHouse Cloud ClickPipes can connect via Multi-VPC PrivateLink
- Both IAM and SCRAM authentication available (flexibility for different consumers)
- Provisioned cluster provides more predictable performance
- Multi-VPC also useful for Databricks connectivity in future

### Negative

- Higher monthly cost (~$300/month vs $50-150/month)
- Provisioned cluster is always running (no auto-pause like Serverless)
- More operational overhead (monitoring, scaling decisions)

## Lessons Learned / 教訓

1. **MSK Serverless is VPC-internal only** — not suitable for cross-VPC consumers like ClickHouse Cloud
2. **Always validate network connectivity before designing pipeline** — This should have been tested earlier
3. **Phase B (Instaclustr on-prem) won't have this problem** — ClickHouse and Kafka in same network
4. **Instance type matters for features, not just performance** — t3.small vs m5.large differs in feature support
