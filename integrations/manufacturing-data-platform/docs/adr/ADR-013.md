# ADR-013: FSx for ONTAP Sizing, Snapshot Policy, and Storage Design

## Status

**Accepted** — 2026-06-07

## Context / コンテキスト

FSx for ONTAP serves as the payload storage layer (images, video, documents) and optionally the ClickHouse cold tier target. Sizing, Snapshot policy, and volume design must be defined for both PoC (minimal cost) and production projection (capacity planning).

FSx for ONTAP はペイロードストレージレイヤー（画像、動画、ドキュメント）および ClickHouse コールド階層ターゲットとして機能する。サイジング、Snapshot ポリシー、ボリューム設計を PoC（最小コスト）と本番予測（容量計画）の両方について定義する必要がある。

## Decision / 決定

Deploy a **Single-AZ FSx for ONTAP file system** with SSD primary tier and capacity pool tiering for the PoC. Define Snapshot policies for data protection and FlexClone support.

PoC 向けに **Single-AZ FSx for ONTAP ファイルシステム**を SSD プライマリ階層とキャパシティプール階層化で展開する。データ保護と FlexClone サポートのための Snapshot ポリシーを定義する。

## PoC Sizing / PoC サイジング

### File System Configuration

| Parameter | PoC Value | Rationale |
|-----------|-----------|-----------|
| Deployment type | Single-AZ | Cost optimization (Multi-AZ for production) |
| SSD storage capacity | 1,024 GB (1 TB) | Minimum for ONTAP features + payload + cold tier |
| Throughput capacity | 128 MB/s | Minimum tier; sufficient for PoC workload |
| Capacity pool tiering | Enabled (AUTO policy) | Cost-optimize infrequently accessed data |
| IOPS mode | Automatic (3 IOPS/GB = 3,072 IOPS) | Sufficient for PoC |

### Volume Design

| Volume | Purpose | Size | Protocol | Tiering Policy | Snapshot Policy |
|--------|---------|------|----------|----------------|----------------|
| `vol_images` | Quality inspection images | 300 GB | NFS + ONTAP S3 | AUTO (tier after 31 days) | Hourly/Daily/Weekly |
| `vol_videos` | Process monitoring video | 400 GB | NFS + SMB | AUTO (tier after 7 days) | Daily/Weekly |
| `vol_documents` | Quality reports, certificates | 100 GB | SMB + NFS | AUTO (tier after 90 days) | Hourly/Daily/Weekly |
| `vol_clickhouse_cold` | ClickHouse S3 cold tier | 200 GB | ONTAP S3 only | NONE (already cold) | Weekly |

**Total allocated:** 1,000 GB (with 24 GB reserved for ONTAP system)

### SVM Configuration

| Parameter | Value |
|-----------|-------|
| SVM name | `svm-factory-poc` |
| Protocols | NFS v3/v4.1, SMB 3.0, S3 |
| NFS export policy | Allow VPC CIDR (10.0.0.0/16) |
| SMB share | `factory-docs$` (hidden share for documents) |
| S3 bucket names | `factory-images`, `factory-clickhouse-cold` |
| DNS name | Auto-assigned by FSx |

## Snapshot Policy / Snapshot ポリシー

### Policy: `factory_poc_standard`

| Schedule | Keep | Applies To |
|----------|------|-----------|
| Hourly (at :00) | 24 snapshots | vol_images, vol_documents |
| Daily (at 00:00 UTC) | 7 snapshots | All volumes |
| Weekly (Sunday 00:00 UTC) | 4 snapshots | All volumes |

**Space overhead estimate:** ~15-20% additional SSD usage for Snapshot data (with typical manufacturing write patterns).

### Policy: `factory_poc_video`

| Schedule | Keep | Applies To |
|----------|------|-----------|
| Daily (at 00:00 UTC) | 3 snapshots | vol_videos |
| Weekly (Sunday 00:00 UTC) | 2 snapshots | vol_videos |

**Rationale:** Video volumes are large; fewer Snapshots to control space consumption.

## Capacity Pool Tiering / キャパシティプール階層化

| Tiering Policy | Behavior | Volume |
|---------------|----------|--------|
| AUTO | Moves cold data blocks to capacity pool after cooling period | vol_images, vol_videos, vol_documents |
| NONE | Keeps all data on SSD | vol_clickhouse_cold (already cold-tier purpose) |

**Capacity pool cost:** ~$0.0125/GB-month (vs SSD at ~$0.125/GB-month = 10x cheaper for cold data)

### Expected Tiering Behavior (PoC)

```
Month 1: All data on SSD (freshly written)
Month 2: 
  - vol_images: ~50% tiered (old images cold after 31 days)
  - vol_videos: ~80% tiered (old video cold after 7 days)
  - vol_documents: 0% tiered (< 90 day threshold)
Month 3:
  - vol_images: ~65% tiered
  - vol_videos: ~90% tiered
  - vol_documents: ~30% tiered (oldest docs > 90 days)
```

## FlexClone for PoC Testing / PoC テスト用 FlexClone

FlexClone provides instant, space-efficient copies for testing without duplicating payload data:

```bash
# Create instant clone of production-like payload volume for testing
# (Zero additional storage until changes are made)
volume clone create -vserver svm-factory-poc \
  -flexclone vol_images_test \
  -parent-volume vol_images \
  -type RW
```

| Use Case | FlexClone Source | Purpose |
|----------|-----------------|---------|
| ML training data | vol_images | Test ML pipeline without touching production data |
| Schema migration test | vol_documents | Validate parser changes on real-like data |
| Load testing | vol_images | Generate read load without production impact |
| Disaster recovery drill | All volumes | Validate restore procedure |

## Consequences / 結果

### Positive / ポジティブ

- Minimal PoC cost (~$220/month) while validating all ONTAP features
- Capacity pool tiering reduces long-term storage cost by 10x for cold payloads
- Snapshot provides instant recovery without backup infrastructure
- FlexClone enables zero-cost test environments
- Single-AZ is acceptable for PoC (Multi-AZ for production)
- Volume-per-data-type provides clean isolation and independent policies

### Negative / ネガティブ

- Single-AZ has no automatic failover (acceptable risk for PoC)
- 128 MB/s throughput may limit concurrent read performance during ML training
- Snapshot space consumption not precisely predictable until PoC runs
- Capacity pool tiering adds read latency for recalled data (acceptable for cold access)
