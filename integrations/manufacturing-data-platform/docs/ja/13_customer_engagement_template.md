## テンプレート: 製造データプラットフォーム — 顧客ディスカバリー

### 1. 顧客質問の特定

| # | 典型的な顧客の質問 | マッピング先 |
|---|------------------|-----------|
| Q1 | 「工場の品質イベントをリアルタイムで可視化するには？」 | リアルタイム分析 (ClickHouse + Kafka) |
| Q2 | 「NFS/SMB のファイル共有にデータがあり AI チームがアクセスしにくい」 | FlexCache + メタデータ/ペイロード分離 |
| Q3 | 「Databricks を使いたいがデータはオンプレにある」 | ハイブリッドアーキテクチャ (Instaclustr + AWS Databricks) |
| Q4 | 「データをあちこちにコピーしている — ヒストリアン → ETL → DWH → ML」 | FlexCache によるゼロコピー、単一の真実のソース |
| Q5 | 「工場横断で製造データをガバナンスしたい」 | Unity Catalog + schema-per-factory |
| Q6 | 「エッジデバイスが巨大ファイル（画像、動画）を生成する — どう扱うか？」 | メタデータ/ペイロード分離 (ADR-005) |

### 2. 業種パターンマッピング

| 業種 | パターン | 主要コンポーネント |
|------|---------|-----------------|
| 製造（ディスクリート） | 品質検査 + リアルタイム OEE | Kafka + ClickHouse + ONTAP（画像） |
| 製造（プロセス） | センサーモニタリング + 異常検知 | Kafka + ClickHouse + Databricks（ML） |
| 自動車 | ビジョン検査 + トレーサビリティ | ONTAP（動画）+ Kafka + Unity Catalog |
| 半導体 | 計測データ + 歩留まり分析 | ClickHouse（高カーディナリティ）+ Delta Lake |
| 食品・飲料 | 温度モニタリング + コンプライアンス | Kafka + ClickHouse + 監査証跡 |

### 3. ステークホルダーマップ

| 役割 | 関心事項 | 主要メトリクス |
|------|---------|-------------|
| 製造担当VP / 工場長 | 生産稼働率、品質歩留まり | OEE、欠陥率、対応時間 |
| 品質部長 | 欠陥検出速度、トレーサビリティ | 検出時間、監査完全性 |
| IT部長 / CIO | データ統合、コスト、ガバナンス | TCO、データ重複比率、コンプライアンス |
| データサイエンスリード | ML モデル用の工場データアクセス | データアクセス時間、モデルトレーニングスループット |
| オペレーションマネージャー | ダッシュボード鮮度、アラート | ダッシュボードレイテンシ、誤報率 |

### 4. ディスカバリー質問（顧客ミーティング用）

```
□ 工場フロアに現在どのようなデータソースが存在するか？
  (ヒストリアン、PLC、SCADA、MES、品質システム、カメラ)

□ どのプロトコルが使われているか？ (OPC-UA, Modbus, MQTT, NFS, SMB, S3)

□ イベントから可視化までの現在のレイテンシは？
  (リアルタイム？ 分単位？ 時間単位？ 翌日？)

□ 大容量ファイルデータ（画像、動画、ドキュメント）は今どこにあるか？

□ 複数工場はあるか？ 工場間でデータはどう共有されているか？

□ 分析プラットフォームは何を使用/計画しているか？
  (Databricks? Snowflake? カスタム? なし?)

□ コンプライアンス/ガバナンス要件は？

□ 既存のオンプレミスインフラ (NetApp ONTAP, Kafka) はあるか？

□ PoC の予算/タイムラインは？

□ このイニシアチブのビジネススポンサーは誰か？
```

### 5. PoC 成功基準テンプレート

| # | 基準 | 測定方法 | ターゲット | オーナー |
|---|------|---------|---------|--------|
| 1 | リアルタイムイベント可視化 | イベント→ダッシュボードレイテンシ | < 5 秒 | 品質部長 |
| 2 | ガバナンス付きデータレイク | Unity Catalog の Delta テーブル | クエリ可能 | データサイエンスリード |
| 3 | ペイロードアクセス性 | クラウドからの画像取得時間 | < 10 秒 | ML エンジニア |
| 4 | データ損失なし | イベント整合性チェック | 0 損失イベント | IT 部長 |
| 5 | 予算内コスト | 月間 AWS 支出 | < $X/月 | IT 部長 |
| 6 | 障害復旧 | シミュレート障害後のパイプライン再開 | データ損失なしで再開 | オペレーション |

### 6. Go/No-Go チェックリスト

```
□ 全 PoC 成功基準をクリア？
□ コストが合意予算内？
□ ブロッキング技術的問題なし？
□ ビジネススポンサーが価値を確認？
□ 次フェーズ（本番/拡張）スコープ定義済み？
□ 次フェーズの運用オーナーシップ割当済み？
□ ベンダーコミットメント確認済み（Instaclustr, Databricks）？
```

## ペルソナレビューノート

- **ペルソナ 1 (Partner/SI)**: 全 P1 指摘に直接対処。パートナーがディスカバリー質問を顧客会議で使用可能。PoC 成功基準テンプレートは再利用可能。
- **ペルソナ 4 (成果)**: ビジネス成果がステークホルダーにマッピング。成功基準に測定可能なターゲットとオーナー含む。
- **ペルソナ 10 (プロダクト)**: 明確な判断ポイントの Go/No-Go チェックリスト。GO 判断に次フェーズスコープ必須。
- **機密性**: ✅ Pass — テンプレートはジェネリック。顧客固有情報なし。業種例は公知。
