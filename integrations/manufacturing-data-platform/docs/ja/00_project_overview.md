## 製造データプラットフォーム PoC — アーキテクチャ検証

### 目的

本プロジェクトは、エッジ/工場データパイプラインを Databricks Unity Catalog と統合する AWS ベースの製造データプラットフォームアーキテクチャを、**S3 アクセスポイントに依存せずに**検証する。

目標は、提案アーキテクチャが PoC として実現可能かどうか、また以下の用途における信頼性のあるアーキテクチャパターンとなり得るかを判断すること：

- 製造データの統合
- リアルタイム分析
- 下流の AI/分析アクティベーション

### アーキテクチャ仮説

S3 アクセスポイントを通じてオブジェクトストレージを Databricks Unity Catalog と直接統合する代わりに、本アーキテクチャは以下を使用する：

| コンポーネント | 役割 |
|--------------|------|
| Apache Kafka (Amazon MSK) | 工場データイベントバックボーン — 構造化イベントと軽量メタデータの伝送 |
| ClickHouse | リアルタイム分析エンジン — 高頻度センサー/品質データに対するサブ秒クエリ |
| FSx for ONTAP | 大容量非構造化ペイロード（ドキュメント、画像、動画）のストレージレイヤー |
| Databricks + Unity Catalog | 下流のガバナンス付き分析・AI プラットフォーム — キュレーション済み Delta テーブル |
| ネイティブ Amazon S3 | Unity Catalog が管理する Delta Lake テーブルの物理ストレージ |

### データフロー概要

```
エッジ/工場 → MQTT/Kafka プロデューサー → Kafka トピック
                                              ↓
                                  ┌───────────┼───────────┐
                                  ↓           ↓           ↓
                            ClickHouse   Databricks    FSx for ONTAP
                            (リアルタイム  (Structured   (ペイロード格納:
                             分析)         Streaming     画像、動画、
                                           → Delta)      ドキュメント)
                                  ↓           ↓
                             ダッシュボード  Unity Catalog
                                           管理テーブル
                                           (ネイティブ S3 上)
```

### 主要設計決定

| ID | 決定 | 理由 |
|----|------|------|
| DEC-001 | Delta Lake テーブルはネイティブ Amazon S3 に格納 | Unity Catalog の外部ロケーションはネイティブ S3/ADLS/GCS/R2 のみサポート。S3 互換エンドポイント（ONTAP S3 含む）は非サポート。 |
| DEC-002 | Kafka を Databricks への主要取り込みパスとする | Structured Streaming は Delta テーブルへの書き込みで正確に1回のセマンティクスを保証。実績のある本番パターン。 |
| DEC-003 | ClickHouse をリアルタイム運用分析に使用 | 高カーディナリティの製造データに対するサブ秒クエリレイテンシ。Databricks の代替ではなく運用ダッシュボードの補完。 |
| DEC-004 | FSx for ONTAP を非構造化ペイロードストレージに使用 | マルチプロトコルアクセス（NFS/SMB/S3）、Snapshot、SnapMirror、エンタープライズデータ保護。Delta テーブルはパス/URI でペイロードを参照。 |
| DEC-005 | S3 アクセスポイントへの直接依存なし | アーキテクチャは S3 アクセスポイントなしで動作。ペイロードは FSx for ONTAP に格納し、メタデータとキュレーション済み分析データは Kafka 経由でネイティブ S3 に格納。 |

### プロジェクトスコープ

- 技術調査と検証（本番デプロイではない）
- 公開 GitHub リポジトリ（機密情報なし）
- バイリンガルドキュメント（日本語が主、英語が並行）
- 引用付きのエビデンスベース評価
- 最小限のコンポーネントによる PoC 設計

### スコープ外

- 本番デプロイ
- 実顧客データ
- ベンダー商業交渉
- 規制コンプライアンス認定
- 大規模パフォーマンスベンチマーク
