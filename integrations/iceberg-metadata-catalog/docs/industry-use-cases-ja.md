# 業種別ユースケース: 非構造化データ向け AI メタデータカタログ

🌐 日本語 | [English](industry-use-cases.md)

## エグゼクティブサマリー

本ソリューションは、既存の NAS ストレージ上の非構造化ファイル（PDF、画像、CAD、動画、ログ）を、データのコピーや既存ワークフローの変更なしに、即座に検索可能・AI 分類可能にします。

**主要な価値**: SQL で 2 秒未満で任意のファイルを発見、自動分類と機密データ検出、アクセス統制 — すべて S3 へのデータコピーより低コスト。

## 製造業

### ビジネス課題

| 課題 | 現状 | 影響 |
|------|------|------|
| 設計文書の検索 | フォルダを手動で探索、同僚に確認 | 検索に数時間、納期遅延 |
| ISO 監査時の文書取得 | 監査前に文書を探し回る | 監査指摘、不適合リスク |
| 品質報告書のトレーサビリティ | スプレッドシートで管理 | 不完全なトレーサビリティ、リコールリスク |
| 重複ファイルの検出 | 把握できていない | ストレージの無駄、バージョン混乱 |

### デモシナリオ（製造業）

```bash
# 製造業サンプルデータ生成
python demo/sample-data/generate-sample-data.py --industry manufacturing --count 100

# デモ実行
./demo/scripts/run-demo.sh --ap-alias <alias>
```

**デモトーキングポイント**:
- 「ポンプハウジング P-2000 の全設計図面を検索」→ 1.8 秒
- 「温度逸脱に言及している QC レポートは？」→ AI 分類済み、即時取得
- 「前回の ISO 監査以降に変更されたファイルを表示」→ 時間範囲クエリ

### コンプライアンス対応表

| 要件 | 本ソリューションでの対応 |
|------|------------------------|
| ISO 9001 §7.5（文書管理） | 全文書がメタデータ付きでカタログ化、Iceberg タイムトラベルによるバージョン追跡 |
| ISO 9001 §8.5.2（トレーサビリティ） | file_id が部品番号、ロット、検査記録にリンク |
| IATF 16949（自動車） | 自動車品質記録の分類 + 保持メタデータ |
| 文書保持 | Iceberg スナップショット保持 + S3 ライフサイクルポリシー |
| アクセス制御 | Lake Formation による部門/ロール別グラント |

### ROI 試算（製造業、5万ファイル）

| 項目 | Before | After | 削減効果 |
|------|--------|-------|---------|
| 文書検索時間 | 15分/検索 × 20回/日 | 5秒未満/検索 | **1日5時間の回復** |
| ISO 監査準備 | 2週間 | 2日 | **8日間短縮** |
| ストレージ（S3 コピー不要） | $125/月 | $0 | **$125/月削減** |
| AI 分類の人件費 | 2 FTE-時間/日 | 自動化 | **年間約500万円** |

## 公共機関

### ビジネス課題

| 課題 | 現状 | 影響 |
|------|------|------|
| 情報公開請求への対応 | ファイル共有を手動検索 | 対応に数日〜数週間 |
| 個人情報の所在把握 | どのファイルに PII があるか不明 | コンプライアンスリスク |
| 文書保持期間の遵守 | 手動追跡 | 誤削除または過剰保持 |
| 部門間の文書共有 | メール添付、USB | セキュリティリスク |

### コンプライアンス対応表

| 要件 | 本ソリューションでの対応 |
|------|------------------------|
| 情報公開法 | 即時文書発見 + PII 自動墨消し |
| 個人情報保護法 | PII 検出（英語7種、日本語7種）+ 匿名化 |
| 行政文書管理ガイドライン | 分類 + 保持メタデータ + 監査証跡 |
| データレジデンシー | 全データが同一 AWS リージョン内、国境を越えた転送なし |
| アクセスログ | CloudTrail + Lake Formation 監査 |

### 調達仕様書テンプレート

公共機関の調達に含めるべき要件:

```
1. 元データのコピーや移動なしに非構造化ファイルをカタログ化できること
2. 英語および日本語の文書で PII を検出できること
3. SQL ベースの検索で 5 秒以内の応答時間を提供すること
4. メタデータへの全アクセスの監査証跡を維持すること
5. ロールベースアクセス制御（RBAC）をサポートすること
6. 単一の AWS リージョン内で動作すること（データレジデンシー）
7. 信頼度スコア付きの自動文書分類を提供すること
8. 文書保持ポリシーの適用をサポートすること
9. 100万ファイル以上にパフォーマンス劣化なくスケールすること
10. コスト透明性を提供すること（従量課金、スケールトゥゼロ）
```

## PoC 提案テンプレート（社内稟議用）

**タイトル**: AI メタデータカタログ PoC — 非構造化データの発見とガバナンス

**目的**: 既存 NAS 上の [X] ファイルを、データ移行なしに即座に検索可能・AI 分類可能にする実現可能性を評価する。

**スコープ**:
- 対象: [ボリューム/共有名] 内の [ファイルタイプ]
- ファイル数: [推定]
- 期間: 2週間（セットアップ1週間、評価1週間）

**期待される成果**:
- ファイル発見時間: 数分 → 数秒
- PII インベントリ: 不明 → 定量化
- 文書分類: 手動 → 自動化
- コスト: PoC 全体で $100 未満

**必要なリソース**:
- FSx for ONTAP S3 Access Point（読み取り専用、infrastructure-request-template-ja.md 参照）
- Bedrock、Athena、S3 Tables アクセス可能な AWS アカウント
- データエンジニア 1名（パートタイム、1週間）

**成功基準**:
- [ ] 100+ ファイルがカタログ化され SQL で検索可能
- [ ] AI 分類精度がサンプルセットで 80% 以上
- [ ] PII 検出が既知の機密ファイルを特定
- [ ] クエリ応答時間 5 秒未満
- [ ] PoC 総コスト $100 未満

**リスク**: ゼロ。既存ファイルへの読み取り専用アクセス。データ移動なし。ワークフロー変更なし。完全に可逆（CloudFormation スタック削除）。
